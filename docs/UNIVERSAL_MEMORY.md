# Aether Universal Memory

Status: P0 architecture

## Purpose

Universal Memory gives Aether continuity across ChatGPT, Codex, Hermes, Gemini, Grok, Notion, Google Drive, GitHub, Apple capture, web research, local files, and future providers without treating every captured token as permanent truth.

## Memory layers

1. **Raw evidence** — immutable/source-faithful captures such as chats, documents, tool outputs, files, and run artifacts.
2. **Normalized objects** — parsed content with stable IDs, hashes, timestamps, source metadata, project links, and sensitivity labels.
3. **Retrieval projections** — chunks, full-text indexes, embeddings, entity relations, and temporal projections; all rebuildable.
4. **Memory candidates** — extracted facts, preferences, decisions, procedures, constraints, and summaries awaiting promotion.
5. **Canonical memory** — durable state accepted by policy with provenance, confidence, freshness, sensitivity, and supersession metadata.
6. **Working context** — ephemeral task/session context that expires or is summarized after use.

## Evidence lake vs machine memory

Google Drive is the human-accessible evidence/artifact lake. The private Aether data plane stores structured machine state, sensitive source objects, indexes, relationships, and canonical memory. Notion presents human operational state. GitHub stores executable/versioned truth.

No vector store or embedding index is a source of truth.

## Normalized source envelope

Every importer should produce fields equivalent to:

- source system
- external stable ID
- capture/update timestamps
- content type
- content hash
- raw object URI/reference
- project/objective refs
- sensitivity and tenant scope
- model/tool/provider metadata where relevant
- parent/related source refs
- attachment/artifact refs

Idempotency key: `source_system + external_id + content_hash`.

## Memory candidate schema

A candidate should include:

- statement/value
- memory type (`fact|preference|decision|procedure|constraint|project_state|summary`)
- source refs
- extracted-at timestamp
- confidence
- freshness horizon
- sensitivity
- project/tenant scope
- conflict set
- promotion status
- supersedes/superseded-by refs

## Promotion policy

Promote when the information is materially useful beyond the immediate task and one or more of the following hold:

- explicitly confirmed by the owner or authoritative source
- repeated consistently across independent evidence
- generated by an approved decision/workflow with traceable provenance
- stable project state required for future work

Do not promote greetings, transient wording preferences, low-confidence model inference, unverified third-party claims, or sensitive material without a legitimate future need.

## Contradictions

Conflicting evidence coexists. The system classifies conflicts as:

- temporal supersession
- conditional difference
- source disagreement
- genuine unresolved contradiction
- extraction error

Aether may auto-resolve only when policy and evidence clearly establish supersession or conditional scope. Otherwise it asks the owner or preserves uncertainty.

## Retrieval

Retrieval is hybrid and permission-aware:

metadata filters + full-text/BM25 + vector similarity + graph/entity relations + recency/freshness + confidence + authority/source quality.

Retrieval first applies tenant, project, sensitivity, provider-disclosure, and retention policy. Relevance ranking happens only within allowed material.

## Privacy boundaries

Each memory/source object carries tenant/project/sensitivity scope. Cross-client disclosure is denied by default. Provider-aware disclosure can restrict material to local Hermes or approved providers.

## Deletion and retention

Deletion must address source objects, canonical memory, derived indexes, cached context packs, and downstream copies within Aether's control. Derived indexes are rebuilt after deletion where necessary.

Retention may differ by class: ephemeral working context, operational telemetry, raw evidence, customer records, and canonical memory should not share one default lifetime.

## Quality metrics

Track:

- retrieval precision/recall on held-out tasks
- stale-context rate
- wrong-memory promotion rate
- contradiction detection rate
- forbidden-context leakage rate
- duplicate-ingestion rate
- provenance completeness
- owner correction/undo rate

## Principle

Google Drive may preserve broad evidence. Aether should believe selectively, retrieve minimally, disclose narrowly, and always be able to explain why a durable memory exists.
